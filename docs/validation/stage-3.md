## Разбор PDF и нормативов

Визуально просмотрены все 64 кандидата исходной эвристики и дополнительная страница 135 руководства 536 РЭ из сортированного извлечения. Объединённый список содержит 65 страниц: 54 иллюстрации/чертежа, три обложки, страницу для заметок и семь страниц со сканированными таблицами либо текстом. Иллюстрации не объявлены пустыми; они классифицированы и не используются как прочитанные числовые нормативы.

Сканированные страницы 236 РК: 144, 271, 272, 273, 277, 278, 280. Страница 144 содержит повёрнутую таблицу; другие страницы включают режимы обкатки/испытаний и несколько моделей двигателей. Автоматическая выдача их чисел без OCR и сверки запрещена. Реестр классификаций и изображения находятся только в `corpus/review/`.

Отдельно визуально сверены четыре полные нормативные выдержки: 236 РЭ, PDF 19; 536 РЭ, PDF 158; 5234 РК, PDF 9; 409 РК, PDF 77. Проверены числа, единицы и условия. Допуск относится к конкретной выдержке и двигателям, а не ко всей странице или таблице. Числа, взятые из непроверенных строк на той же странице, не допускаются.

Новый локальный реестр `decisions.json` привязан к SHA256 PDF. Числовое утверждение допускается только с полной сверенной выдержкой, нужным двигателем и режимом operation/bench. Цитата без условий измерения отвергается. При изменении PDF перестроение и повторная проверка обязательны; приложение дополнительно сверяет SHA256 оригинала перед использованием источника и открытием PDF. Запись проверки и полный текст OCR не публикуются.

Команда `python -m mechanic.review` записывает визуальное решение, поворот, проверенный OCR-текст и числовые выдержки. Она не заменяет просмотр страницы автоматической отметкой. Схема индекса обновлена до версии 2; старый индекс требует перестроения.

## Поиск, применимость и отсутствие основания

FTS5/BM25 сохраняет фильтр двигателя в MATCH до ранжирования. Единая русская нормализация применяется к корпусу и запросу; F01–F14 раскрываются в названия справочника и не трактуются как номера разделов. Кандидаты ранжируются по покрытию значимых слов и BM25 без использования идентификаторов контрольных вопросов либо ожидаемых страниц.

Проверены запросы по всем четырнадцати типам на подходящих группах двигателей. Получены фрагменты документации; это проверка поиска по тематике, а не доказательство наличия специальной процедуры для любого кода на любой машине. Неподходящая для двигателя неисправность не разрешает использовать чужой документ.

Явно запрошенная другая модель/модификация отклоняется. При проверке выдержки учитывается ближайшая предшествующая модель и режим: ЯМЗ-238 не переносится на ЯМЗ-236, модификации ЯМЗ-536 и двух УАЗ не смешиваются, норматив обкатки не выдаётся за эксплуатационный. Неоднозначные случаи остаются предметом отдельной смысловой проверки LLM; серверные проверки не объявляются универсальным пониманием любой таблицы.

Пустой запрос, отсутствие фрагментов и тема без достаточных технических опор дают ограничение без рекомендации и заявки. Для оценки достаточности темы используются лексические признаки корпуса; возможен консервативный отказ при непривычных терминах. Отказ не объявляется доказательством отсутствия инструкции в оригинальном PDF. Чужие/несуществующие страницы, неподтверждённые числовые строки и непроверенный OCR не проходят реестр допустимых источников. Числа сравниваются отдельными токенами: 10 не считается подтверждённым числом 100.

## Контрольный набор и результаты

Вопросы и ожидаемые страницы исходного массива из 24 случаев не изменялись при этой доработке. Визуально проверены основания всех 16 положительных случаев; восемь отрицательных описывают другую модель или процедуру обновления автопилота, которой руководства двигателей не обосновывают. Есть перефразировки, нормативы, общие процедуры и четыре контекста предыдущей реплики; восемь случаев выделены holdout. SHA256 канонического массива вопросов:

`e5901d2b7ca3025b5b5ab3b1beec9b28037ca33d56a1afc695cc0c8ea3e3a013`

Результат `python -m mechanic.evaluate`: **16/16** ожидаемых страниц в первых пяти фрагментах, включая все нормативы и отложенные положительные случаи; **8/8** отрицательных вопросов отклонены проверками применимости/достаточности до LLM. Отдельный интеграционный тест подтверждает, что на этих восьми вопросах агент не обращается к модели, ML или ТОиР и не сохраняет черновик.

Это выполненная приёмка поиска и серверных отказов по задаче 3.8. Смысловая приёмка реальных ответов LLM по задаче 5.7 не подменяется этим результатом: `live_model_semantics_verified=false`, `full_acceptance_passed=false`. API-ключи и модели всё ещё не настроены.

Общий набор проверки: **74 passed**, из них 54 проверки приложения и 20 штатных тестов организатора. Два предупреждения относятся к Starlette TestClient/httpx и устаревшему ByteString в установленной версии PyMuPDF. Проверены в том числе неверная модификация, обкатка вместо эксплуатации, число из непроверенной таблицы, неполная нормативная цитата, несуществующая страница, замена исходного PDF, неподготовленные OCR-языки без потери старого индекса и исключение материалов из исходного архива.

## Исключение материалов из поставки

Шесть PDF удалены только из текущего индекса Git с `--cached`; локальные файлы сохранены, SHA256 совпадают с исходным манифестом. .gitignore исключает руководства, индекс, визуальные материалы, OCR и реестр проверки. Старая история исходных веток по-прежнему содержит PDF: её нельзя публиковать как есть. История не переписывалась.

`python -m mechanic.package` создаёт локальный ZIP по списку разрешённых исходников. Проверены отсутствие PDF, индексов, `corpus/`, реестра извлечённых текстов, секретов и истории `.git`. Публичная отправка не выполнялась. README описывает получение PDF отдельно от организатора и локальное построение/повторное построение корпуса; отсутствие материалов даёт понятную инструкцию.

## Оставшийся блокер задачи 3.2

В рабочей среде нет доступных `eng.traineddata` и `rus.traineddata`. Прямая загрузка официальных данных Tesseract заблокирована сетью; GitHub-подключение возвращает пустое содержимое для крупных файлов и не поддерживает чтение этих бинарных blob. Поэтому успешная OCR-обработка не заявлена. Команда `--ocr` возвращает понятную ошибку до замены индекса; предыдущий корпус остаётся доступным.

Для завершения 3.2 нужны локальные языковые файлы в TESSDATA_PREFIX, запуск OCR семи сканированных страниц с нужным поворотом, сверка текста/таблиц и допуск только проверенных выдержек. Публикация языковых файлов или извлечённых из руководств текстов для завершения этапа не требуется.
