Первый запуск внутри песочницы не смог сохранить локальный JSON-отчёт (`PermissionError`), поэтому его результат не использован как подтверждение API. После разрешённого запуска вне песочницы получены перечисленные выше HTTP 200. Это не изменение сетевой конфигурации приложения. Локальные диагностический скрипт и машиночитаемый результат находятся в игнорируемых `corpus/llm-access-probe.py` и `corpus/llm-access-current.json`. Проверка не делает повторов при HTTP 429/5xx: диагностический обработчик сохраняет реальный статус и завершает вызов адаптера как ошибку.

## Выбор провайдера и статус 1.4

Технический выбор основного провайдера для демонстрации: **OpenAI / gpt-6-luna**, согласно текущим настройкам и успешному запросу. Выбор условен до подтверждения допустимости фактического региона сервера и пользователей. Yandex остаётся альтернативным адаптером с зафиксированным ограничением «не настроен»; недоступность самого сервиса этим не доказана. Автоматическое переключение и изменение `.env` не выполнялись.

**1.4 остаётся открытой до подтверждения региона и окончательного выбора допустимого демонстрационного провайдера.** Если фактический регион не поддерживается OpenAI, успешный HTTP-ответ не снимает это ограничение: по design.md потребуется явно выбрать и проверить доступный Yandex. Успешная короткая генерация подтверждает API-контракт и текущий доступ, но не смысловую пригодность ответов по руководствам: 5.7 и 8.1 остаются открытыми.

Для завершения 1.4 требуется страна размещения сервера и страна доступа пользователей на демонстрации. Настройка часового пояса Europe/Moscow не определяет эти страны. В официальном списке OpenAI Россия отсутствует; список перепроверен 27 ноября. Остаток API-баланса и количественные лимиты нельзя вывести из ответа HTTP 200; для планирования нагрузки их проверяют в аккаунте отдельно.

## Официальные источники, проверенные 27 ноября

- [Поддерживаемые страны и территории OpenAI](https://help.openai.com/en/articles/7947663-chatgpt-and-openai-api-supported-countries-and-territories): доступность привязана к перечисленным странам, успешное сетевое соединение не заменяет проверку региона.
- [GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna): официальная карточка модели; доступ конкретного ключа дополнительно проверен запросами выше.
- [Ошибки OpenAI API](https://developers.openai.com/api/docs/guides/error-codes): различать ошибки частоты запросов и ограничения биллинга/квоты; для причины проверять `error.code`, а не один HTTP 429.
- [Начало работы с Yandex AI Studio](https://aistudio.yandex.ru/ru/docs/ai-studio/quickstart/): для используемого режима оплаты по потреблению нужны каталог, активный платёжный аккаунт и API-ключ.
- [API-ключ Yandex](https://aistudio.yandex.ru/ru/docs/ai-studio/operations/get-api-key), [модели Yandex](https://aistudio.yandex.ru/ru/docs/ai-studio/concepts/generation/models): учётные данные и доступную модель нужно проверить для конкретного аккаунта перед переключением.

## Результат

- Settings.load() читает заполненные ключ и модель OpenAI; llm_problem() возвращает null. Настроенная модель — gpt-6-luna. Её существование и доступность для этого аккаунта ещё не подтверждены ответом API.
- Наш процесс приложения на 8010 перезапущен после изменения .env; /api/session возвращает provider=openai и llm_problem=null. Текущий PID — 14572. Отсутствие предупреждения означает наличие настроек, а не успешную проверку доступа.
- Один вызов штатного Provider.json с коротким запросом JSON без руководств завершился сетевой ошибкой до HTTP-ответа. DNS api.openai.com разрешается. Проверка TCP-соединения с портом 443 выявила PermissionError, errno=13, WinError=10013: доступ к сокету запрещён правами. Это подтверждает отказ исходящего соединения в текущей среде, но не определяет конкретное правило Windows/защитного ПО.
- HTTP-ответ API не получен: действительность ключа, допустимость региона, биллинг/квоты и модель не проверены. Затраты и задержки успешного обращения не измерены. Подмена модели, смена провайдера, отключение защиты или обход запрета не выполнялись.
- Yandex не настроен: полный набор ключа, folder_id и модели отсутствует. Проверка его DNS не подтверждает доступ к аккаунту/API.
