## Настройка GigaChat

Локально скопируйте `.env.example` в `.env`, если файла ещё нет. Укажите:

```dotenv
LLM_PROVIDER=gigachat
GIGACHAT_AUTH_KEY=
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_MODEL=GigaChat-3-Ultra
GIGACHAT_CA_FILE=
```

В `GIGACHAT_AUTH_KEY` подставьте готовый ключ авторизации из кабинета, строку Base64 без префикса `Basic`. Отдельное поле Client ID не нужно. `GIGACHAT_CA_FILE` заполняют путём к доверенному PEM, если системе не хватает сертификата. Адаптер использует TLS и официальный endpoint. Для переключения провайдера перезапустите приложение. [Авторизация](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/gigachat-api) · [GigaChat 3 Ultra](https://developers.sber.ru/docs/ru/gigachat/models/gigachat-3-ultra) · [Сертификаты](https://developers.sber.ru/docs/ru/gigachat/certificates).

Квота Freemium допускает один одновременный поток на учётную запись. Для локального стенда используйте один процесс Uvicorn и последовательный прогон. При HTTP 429 проверьте одновременные вызовы и квоту проекта в кабинете. [Квоты](https://developers.sber.ru/docs/ru/gigachat/limitations).

## Повторить проверку

1. Подготовьте локальный PDF-корпус и визуально сверенные числовые записи по [README](../../README.md). Для сопоставимого результата нужны те же решения сверки. Реестр с выдержками хранится локально.
2. В PowerShell из корня ветки выполните:

   ```powershell
   New-Item -ItemType Directory -Force dist | Out-Null
   .\.venv\Scripts\python.exe scripts/check_llm_dataset.py --live --workers 1 --report dist/gigachat-dataset.json 2> dist/gigachat-dataset.log
   ```

3. Добавьте `--case 236-norm` для одного случая. Скрипт отправляет вопросы и найденные выдержки выбранной внешней модели. Он не вызывает ML и ТОиР. Отчёт содержит ID случая, HTTP, исход, задержку и ID действия. Для сквозной проверки запустите две локальные заглушки по README, выберите известную пару и остановитесь на предпросмотре.
4. В событии `llm.auth` проверяйте исход OAuth. В `llm.request` смотрите HTTP, стадию, задержку, входные и выходные токены. По `X-Action-Id` сопоставляйте действия с `search.result` и `verify.result`. [Порядок сбора журнала и карта ошибок](dima-debug.md).

Ключ и токен OAuth передаются только серверному адаптеру. Для передачи Сергею используйте защищённый канал учётных данных. К отчётам об ошибках прикладывайте технические поля без исходных ответов модели, выдержек, токенов подтверждения и cookie.
