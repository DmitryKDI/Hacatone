# Приёмка P0 с реальными службами

27 ноября 2026 года, МСК. Изменение `hackathon-mvp`. Использован тот же корпус из шести руководств и замороженный набор из 24 вопросов. Работающий провайдер OpenAI `gpt-6-luna`. Yandex не настроен.

| Проверка | Фактический результат |
|---|---|
| Локальный поиск | 16 из 16 ожидаемых страниц в результатах поиска, 8 из 8 отрицательных случаев с отказом |
| Ответы LLM | Один полный повтор и точечные повторы после исправлений. По последнему сохранённому результату каждого вопроса 14 из 16 положительных случаев содержат ожидаемые страницы, два показывают конфликт. Все восемь отрицательных случаев блокируются |
| Неверные связки и сравнение инструкций | 8 из 8 в последнем отдельном повторе на OpenAI. Неверный узел, описание вместо работы, подмена единицы и чужая модификация блокируются. Проверены два документа, две страницы, неизвестная модификация и разные условия |
| Интеграция с ML | Все 195 пар через работающую службу. 111 нормальных, 69 с отклонением, 15 непригодных. Отдельный прогон выполнялся с отключённой LLM и проверял их реакции и запреты отправки |
| Регрессия | 148 Python-тестов, один пропуск интеграции в обычном запуске. Отдельный интеграционный тест 195 пар прошёл. 5 тестов интерфейса прошли |

Цитаты из показанных ответов сверены с текстом соответствующих физических страниц. Это проверка происхождения цитат. Полная ручная оценка смысла и применимости каждого ответа остаётся условием 5.7. Набор и ожидаемые страницы сохранены. Результаты после точечных повторов относятся к нескольким версиям кода, поэтому их следует отличать от единого повтора на финальном кандидате. Детальные ответы и выдержки сохранены локально в `corpus/live-semantics/`.

Два случая требуют сверки применимости. В `236-paraphrase` показаны разные инструкции для ремня водяного насоса в разделах руководства ЯМЗ-236. В `409-general` на физических страницах 194–195 руководство ЗМЗ сначала описывает замену или правку ведомого диска при конкретной неисправности, затем сообщает об общем правиле замены непригодных дисков. Выбор между указаниями зависит от того, является ли первая строка допустимым исключением в условиях выбранной машины. Присутствие этих выдержек само по себе не даёт полномочий выбрать ремонтную работу.

Исправлена ложная трактовка слов после числа как единиц измерения и добавлена нормализация эквивалентного десятичного написания. Модель выбирает идентификатор рабочего фрагмента, а приложение восстанавливает буквальную выдержку. При предпросмотре сохраняются источники текущей диагностики и последнего подтверждённого ответа. При смене проверки состояние сбрасывается. Каждая работа проходит проверку источника, чисел, применимости и независимую проверку смысла.

Сквозная проверка выполнялась через приложение на `127.0.0.1:8000`, службы организатора на 8001 и 8002 и внешний OpenAI API. Для `M739BA198 / S-0103` получены реальная диагностика клапанного механизма и уточняющий ответ по способу измерения. Последующий результат предпросмотра и подтверждения записывается отдельно ниже.

## Продолжение в облачной среде

На исходной версии `7bfcd0b` поиск «Проверка клапанного механизма» для `M739BA198 / S-0103` находил пять фрагментов руководства ЗМЗ-5234, но каталог для заявки не выдавал ни одной допустимой процедурной выдержки: длинные отрывки исчерпывали лимит. Предпросмотр теперь резервирует часть того же лимита для процедур, прошедших предварительную проверку. Если сохранённые фрагменты содержат только описание, агент сначала ищет процедуру. Ответ без работ может получить одну попытку исправления. Финальная проверка источников, отдельная смысловая проверка и подтверждение механика обязательны.

Изолированный прогон на той же паре прошёл диагностику, уточнение и предпросмотр со ссылкой на физическую страницу 20. Запрос к отдельному экземпляру ТОиР выполнен один раз после действительного подтверждения. Экземпляр вернул `TKT-0001`, повтор подтверждения получил HTTP 409. Для прогона использованы выданные службы ML и ТОиР через ASGI и контролируемые ответы в HTTP-адаптере LLM. Внешний API не вызывался, в облачной среде нет настроенного ключа. Индекс перестроен из шести PDF без локальных дополнений Windows OCR и последних ручных пометок; результат не закрывает 5.7 и 8.1.

Поиск на перестроенном индексе дал 16/16 ожидаемых страниц и 8/8 отказов. Прошли 150 Python-тестов и пять тестов JavaScript. Opt-in прогон с отдельными HTTP-сервисами пропущен.
