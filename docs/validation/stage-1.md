## Данные и правила

В парке 50 машин, пять обозначений двигателей и четыре группы руководств. Данные содержат 111 normal, 69 anomaly и 15 check_failed; качество: 163 good, 17 warning, 15 bad. Все пары уникальны, у машины 3–5 проверок, принадлежность проверок и диапазоны оценок согласованы.

Последовательность проверки правил:

1. check_failed либо bad требуют повторить запись и запрещают диагностический вывод/заявку независимо от confidence и anomaly_score.
2. Норма означает отсутствие отклонения данной проверкой, без заявки по этому результату.
3. Для пригодного anomaly предупреждение возникает при warning либо confidence < 0.70. В выданных данных таких случаев 17; остальных пригодных отклонений — 52.
4. Ровно 0.70 при good не даёт предупреждения по confidence. Null не заменяется на ноль; для пригодного anomaly отсутствие оценки означает некорректный ответ.

Дополнительно проверены ближайшее представимое число ниже 0.70, ровно 0.70, ближайшее число выше 0.70, warning при высокой уверенности, bad при высокой уверенности, check_failed при good, check_failed с null, anomaly с null и норма. Все девять случаев дали ожидаемую ветку. Это отдельная проверка интерпретации плана, не проверка ещё не созданных серверных запретов.

Confidence не используется для определения опасности. Основания urgency из design.md сохраняются: high — подтверждённые руководством серьёзный риск и срочная проверка; low — документально обоснованное плановое действие; medium — исходный уровень обоснованной дефектовки без оснований для крайних уровней. Отсутствие источника запрещает отправку при любом уровне. Приёмка смысловой обоснованности конкретных приоритетов на PDF относится к задачам корпуса и ответов, здесь она не объявляется выполненной.
