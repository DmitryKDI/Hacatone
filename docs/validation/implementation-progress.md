# Реализация следующих этапов

26 ноября 2026 года реализованы основа приложения и независимые от аккаунтов части этапов 3–6. Приложение и заглушки проверены через реальные локальные HTTP-запросы. Полный сквозной сценарий с реальным LLM не подтверждён: API-ключи и модели не настроены. P0, приёмка всех руководств и материалы сдачи не объявляются завершёнными.

## Что реализовано

- Одно приложение FastAPI/Jinja2 с обычными CSS/JavaScript. Адаптивный экран содержит выбор машины/проверки, вердикт в чате, вопрос по руководству, предпросмотр и подтверждение отправки. HTML, CSS и JavaScript обслуживаются локально, без сборки фронтенда.
- Настройки из локального .env и переменных процесса. Ключи скрыты в представлении Settings, не возвращаются браузеру, ошибки API не выводят тела ответов поставщика. Неподготовленный корпус и отсутствие ключа объясняются явно.
- Загрузка всех 50 машин / 195 проверок. Отсутствующая модель автомобиля не выдумывается; результат диагностики запрашивается по HTTP, а не читается из истории вместо API.
- Строгая модель ML v6, сверка пары идентификаторов, обработка статусов, null и непригодного качества. Норма и сбой доступны без LLM. Предупреждение следует правилу warning либо confidence < 0.70.
- Реестр шести PDF / 1 743 страниц, локальное извлечение и атомарное построение SQLite FTS5/BM25 с русским стеммингом. Фильтр группы двигателя включён в поисковое условие до ранжирования. Документ, физическая страница, идентификатор фрагмента и SHA256 сохраняются.
- Два HTTP-адаптера LLM с общим JSON-контрактом: OpenAI Chat Completions и Yandex TextGeneration.Completion. Цикл выбора инструмента ограничен пятью шагами / 100 секундами; один вызов ограничен 30 секундами, временная ошибка допускает один повтор. Автоматического переключения провайдера нет.
- Агент выбирает ML, RAG, подготовку заявки или завершение ответа по контексту. Прямая кнопка диагностики является явной пользовательской командой тому же ML-инструменту; дальнейшая цепочка не зашита как обязательная последовательность. Вопрос по руководству может использовать только поиск, без ML или ТОиР.
- Утверждения связаны с проверяемыми выдержками; выдуманные источники, чужая группа двигателя, неподтверждённые числа и добавленные к выдержке операции отклоняются. Отдельный вызов модели проверяет узел, модификацию и условия; неопределённость/ошибка блокирует зависимые рекомендации и заявку. Неподтверждённые запчасти исключаются.
- Сервер формирует точные поля ТОиР v6. Черновик хранится в серверной сессии; машина, проверка, диагноз, приоритет, работы, запчасти и ссылки видны до отправки. Подтверждение связано с конкретным серверным предпросмотром, расходуется до HTTP-запроса. Нет автоматического повтора POST; успех требует 201 и валидного ticket_id/status=created.
- Изоляция сессий, CSRF-токен, ревизия контекста, сброс прежнего черновика при смене пары или новом запросе. Запоздавший ответ старой пары скрывается интерфейсом. Хранение сессий ограничено 200 сессиями и двумя часами; промышленная эксплуатация и постоянная история заявок не заявлены.
- README запуска, отдельная локальная подготовка PDF, инструкции проверки, условия API и перечень лицензий THIRD_PARTY.md. PyMuPDF имеет AGPL/коммерческий режим; проверка лицензий выполнена, выбор лицензии всего проекта для публичной поставки ещё необходим.

## Подтверждённые проверки

Среда: Windows, Python 3.15.2. Версии прямых зависимостей закреплены в requirements.txt; рекомендуемая продуктовая среда Python 3.11 пока отдельно не проверена.

Команда:

```powershell
E:\хакатон\.venv\Scripts\python.exe -m pytest tests neurodvs_hackathon_mock_2026-11-16/tests -q -p no:cacheprovider
```

Результат: **54 passed, 1 warning**, из них 34 проверки приложения и 20 штатных тестов организатора. Предупреждение Starlette о TestClient/httpx сохранилось в предоставленном наборе зависимостей; исходники и зависимости заглушек не изменялись.

Проверки приложения покрывают все 195 ML-записей и принадлежность проверок; приоритет bad над высоким confidence; норму/сбой без LLM; фильтр двигателя; неизвестные и нерелевантные источники; изменённое число и добавленную операцию; исключение неподтверждённых запчастей; выбор RAG без ML; неверное решение инструмента и лимит шагов; структуру запросов обоих API, 401/403/429/503 и непригодный JSON; отсутствие раскрытия ответа с секретом; предпросмотр без отправки; неверный токен; смену пары до подтверждения; точное соответствие отправленного состава; запрет повторного POST при неопределённом результате; изоляцию браузерных сессий и CSRF.

Для каждого провайдера проверены выбор поиска, подготовка заявки и отдельный вызов верификации через реальный код HTTP-адаптера с контролируемым transport. Такие ответы имитируют API только внутри тестов и не используются продуктом. Это проверка контрактов и серверных запретов, а не успешная работа с реальной моделью.

Через реальные локальные процессы приложения и двух заглушек подтверждены GET /, GET /static/app.js, выбор пары, normal, check_failed, anomaly при отсутствии ключа и запрет отправки без предпросмотра. При normal и check_failed — 200 с соответствующим сообщением; при anomaly без ключа — 503 с реальным результатом ML и инструкцией настройки, без фиктивного технического ответа. Проверки первого этапа отдельно подтверждают HTTP-ответы заглушек на все 195 пар.

## Корпус и приёмка поиска

Индекс содержит шесть документов, 1 743 страницы и 2 989 фрагментов. При извлечении с sort=True 42 страницы отмечены needs_review и исключены из подтверждающей выдачи; 1 701 страница имеет текстовый слой. Ранее эвристика на извлечении без сортировки выделяла 64 кандидата. Разница методик не означает, что оставшиеся страницы визуально проверены: исходный список из 64 и таблицы по-прежнему требуют ручного разбора.

Tesseract не обнаружен. Опциональный путь --ocr реализован, но успешная OCR-подготовка не подтверждена. OCR-кандидаты не допускаются к нормативам без проверки; механизма ручного допуска ещё нет. Отсутствие пригодного извлечённого текста не считается доказательством отсутствия инструкции в оригинальном PDF.

Подготовлен tests/data/retrieval_cases.json: 16 положительных и восемь отрицательных вопросов с охватом четырёх групп и шести документов, восемь случаев выделены holdout. В наборе только вопросы и метаданные ожидаемых страниц, без извлечённых текстов. Он имеет статус кандидата: полная визуальная сверка, качественная проверка отрицательных случаев и официальная приёмка ещё не завершены.

`python -m mechanic.evaluate` показал **15/16 попаданий ожидаемой страницы в первые пять результатов**, включая все четыре нормативных и отложенные положительные случаи. Пропущен 236-general (ожидалась PDF-страница 267 руководства по ремонту); его нельзя объявлять успешным по другим найденным страницам. Числовой порог положительной части достигнут, но восемь смысловых отказов и ручная сверка утверждений не выполнены. Поэтому full_acceptance_passed=false и задачи полной приёмки остаются открытыми.

Внутренняя применимость к ЯМЗ-238 / модификациям ЯМЗ-536 / двум ЗМЗ-409 и условиям измерения проверяется модельным верификатором; её достоверность на реальных ответах ещё не подтверждена. Существование ссылки и успех синтетического теста не доказывают правильность нормативов.

Индекс и отчёты его подготовки/оценки находятся в игнорируемой папке corpus/. Передача PDF и текстосодержащих индексов в публичный репозиторий не выполнялась. Исходные ветки пользователя всё ещё содержат PDF в истории; публикация этих веток запрещена. История не переписывалась.
