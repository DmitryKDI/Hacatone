# Архитектура ветки Luna

## Context

В `gigachat` общий адаптер выбирает OpenAI, Yandex или GigaChat. GigaChat требует отдельного OAuth, а UI выводит выбранного провайдера. Агент и верификатор уже используют один интерфейс `Provider.json(system, context)`.

## Goals / Non-Goals

**Цель.** Сохранить проверенную цепочку локального ML, поиска по руководствам, проверки оснований и подтверждения ТОиР, фиксируя единственную модель для всех LLM-шагов.

**Вне задачи.** Новое индексирование, внешние поисковые инструменты, обработка изображений моделью и изменение контрактов заглушек.

## Decisions

- Сохранить интерфейс провайдера и упрощённый OpenAI Chat Completions адаптер. Модель задаётся константой. Отображаемое имя берётся из той же конфигурации. Старые переменные выбора игнорируются.
- Использовать JSON-ответы, существующие ограничения размера, повторы временных ошибок и безопасные ошибки. Сохранить журнал статусов, длительности и токенов. Не записывать заголовки, тела или тексты вопросов. Для запросов указать `store=false`.
- В запросах агента и отдельного верификатора оставить технические поля ML без `vehicle_id` и `session_id`. PDF, индекс, значения окружения и параметры сессии остаются на сервере. В API уходят вопрос и необходимые текстовые выдержки.
- При переносе использовать имеющийся секрет OpenAI, если он доступен. Приватный ключ передаётся через окружение или локальный `.env`. Перед коммитом проверить состав Git и архива. Проверки отказа и сквозного сценария воспроизводятся на локальном управляемом HTTP-ответе.

## Risks / Trade-offs

Доступ к реальной модели зависит от учётной записи и сетевой доступности API. Проверка с управляемыми ответами подтверждает интеграцию и контракт. Для финальной оценки качества нужен внешний запрос с разрешённым ключом и подтверждённым доступом к модели.
