# Дизайн ответов и действий механика

## Context

База для ТЗ — `main`, коммит `44b7b83`. В проекте уже есть карточка вердикта, шесть разделов подробностей, независимая проверка выдержек, блокировка заявок при конфликте и сохранение отметки о сверке меток. Предпросмотр показывает название уровня срочности. Сервер сверяет состав черновика с текущей проверкой и отправляет в ТОиР только после подтверждения.

## Goals / Non-Goals

- Дать один короткий вывод и ближайшее действие перед техническими подробностями. Сохранить проверку источников и действующие ограничения заявки.
- Дать механику контроль над срочностью подходящей заявки и сохранить различие между его выбором и рекомендацией ассистента.
- Настройки автопарка и профили механиков относятся к отдельной задаче после MVP. Внешний контракт ТОиР, поставщик модели и модуль микрофона не требуют изменений для этой задачи.

## Decisions

1. **Краткий и полный ответ.** Использовать существующую карточку над раскрываемыми подробностями. Порядок первой карточки — вывод, следующее действие, затем статус заявки, когда он уместен. Одна или две короткие фразы могут переноситься на несколько строк. Существующие шесть разделов использовать для доказательств и контекста. Пустой раздел скрывать, если он не сообщает значимое ограничение. Понятные состояния оформлять текстом вместе с цветом, пользоваться интерфейсом можно с клавиатуры.
2. **Проверка определяет формулировку.** Типовые исходы переводить в короткие сообщения из известных причин. Сохранять разницу между отсутствием применимого материала, невозможностью проверить ответ и сбоем модели или сервиса. Применимость типа отклонения проверять по подтверждённым данным задачи и карточке. Отсутствие записи об области применимости не считать доказательством несовместимости. Если тип точно неподходящий, блокировать путь к рекомендации и заявке на сервере.
3. **Доказательства сохраняются.** Техническое утверждение переносить на первый экран только после действующей проверки. Обе конфликтующие цитаты показывать рядом с документом и физической страницей. Для сценария ЯМЗ‑236 отдельно обозначить условие демонстрации из ответа организатора, сверив номера страниц с выданными файлами. Для других расхождений конкретное действие — уточнить, какая версия инструкции применима к модификации и условиям, или передать узел на дефектовку по порядку автопарка.
4. **Решение о срочности.** Хранить выбор механика отдельно от приоритета и основания, предложенных моделью. Обновление приоритета привязывать к текущим машине, проверке и действительному черновику; сервер принимает только три допустимых значения. Перед отправкой обновляется предпросмотр и его идентификатор подтверждения. При повторной валидации сервер проверяет работы, источники, выбранную пару и актуальную отметку F7, затем сериализует итоговый выбор в существующее поле контракта ТОиР. Рядом с изменённым значением отображать «Выбрано механиком». Ручной выбор не становится доказательством риска или запрета рейса.
5. **Приёмка.** Использовать существующий зафиксированный набор из 24 вопросов и четыре неверные связки. Сценарии из Q&A добавить как отдельный список. Форму короткой карточки проверить отдельно от качества генерации. Контрольные ответы можно использовать в регрессии, а пригодность текста и оснований дополнительно подтвердить живым прогоном и сверкой с PDF.

## Risks / Trade-offs

- Сокращение ответа может убрать важное условие. Повторить его в кратком действии, если оно влияет на безопасность, и сохранить полную формулировку в источнике.
- Слишком уверенный ответ может превратить акустическую гипотезу в диагноз. Явно помечать источник наблюдения, предполагаемую причину и вывод осмотра.
- Ручная срочность может рассинхронизировать предпросмотр с отправкой. Привязать подтверждение к показанному составу и покрыть замену выбора и смену машины тестами.

## Migration Plan

Изменение можно реализовать поверх актуального `main` без миграции данных. Ручной выбор срочности действует в текущей сессии предпросмотра. Существующие чеки `hackathon-mvp` использовать как ссылки на приёмку. Обновлять их статус по результатам фактических прогонов.
