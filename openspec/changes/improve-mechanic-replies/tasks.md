# Задачи

## 1. Диагностика и первый экран

- [ ] 1.1 Сделать короткую карточку «итог → следующее действие → статус заявки». Проверить норму и пригодное отклонение в `tests/frontend.test.cjs`. На ноутбуке и при ширине 320 пикселей проверить, что действие видно без раскрытия, а управление работает с клавиатуры. Использовать критерий десяти секунд из `hackathon-mvp` 6.1 для чтения вердикта.
- [x] 1.2 Разделить причины отказа на непригодную запись, доказанное расхождение с карточкой, отсутствие источника и недоступный этап. Проверить сообщения для bad, check_failed, warning и несовместимого типа. В заблокированных случаях проверка должна подтверждать отсутствие исходящего запроса в ТОиР.

## 2. Ответы со ссылками

- [x] 2.1 Показывать прямой ответ на закрытый вопрос и конкретное действие при отсутствии применимой инструкции. Проверить два исхода сверки меток F7, вопрос вне корпуса и временную ошибку. Отличить подтверждённый вывод, наблюдение и гипотезу в раскрываемых подробностях.
- [x] 2.2 Показать обе версии спорной инструкции и безопасный следующий шаг. Проверить конфликт по зазорам ЯМЗ‑236, отдельную пометку условия демонстрации и конфликт без решения заказчика. Сверить страницы с PDF и убедиться, что зависимая заявка остаётся заблокированной.

## 3. Предпросмотр заявки

- [x] 3.1 Показать приоритет как действие и срок. Дать механику изменить его в допустимом предпросмотре. Проверить сохранение предупреждения при warning, маркировку ручного выбора и явное подтверждение после обновления.
- [x] 3.2 Связать итоговый выбор с тем же черновиком и проверенной парой. Проверить недопустимое значение, устаревшее подтверждение, смену машины, изменение результата F7 и попытку обхода блокировки. Сервер должен отправить ровно показанный состав с итоговым приоритетом только после отдельного подтверждения.
- [x] 3.3 Сделать понятные сообщения о подтверждении, создании и неопределённом результате. Проверить показ номера при успехе и отсутствие повторного POST после таймаута.

## 4. Сквозная приёмка

- [x] 4.1 Пройти зафиксированные 24 случая и четыре неверные связки из `hackathon-mvp` 5.7. Сверить технические ответы, единицы, условия, PDF и блокировки. Сценарии Q&A проверить дополнительно, сохранив исходный набор.
- [x] 4.2 Пройти на стенде цепочку «диагностика → объяснение → осмотр → предпросмотр → подтверждение → номер ТОиР», затем случай с отказом. Зафиксировать провайдера, какие сервисы использовались, фактические результаты и ограничения. Связать результаты с `hackathon-mvp` 8.1 и 8.4. Регрессию с подставным ответом модели учитывать отдельно от живой приёмки.

Результаты полного прогона, точечных повторов и проверки интерфейса собраны в [отчёте о готовности к записи](../../../docs/validation/improve-mechanic-replies.md). Для 1.1 остаётся замер чтения пользователем за десять секунд.
