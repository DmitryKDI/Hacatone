# Hacatone

## Приложение «Цифровой механик»

Один локальный сервер FastAPI, адаптивный чат, выбор всех 50 машин и 195 проверок, HTTP-инструменты ML/ТОиР, локальный поиск по шести руководствам. Объяснение и выбор инструментов выполняются выбранной LLM; технические утверждения проходят проверку выдержки и отдельную смысловую проверку. При отсутствии ключа приложение честно сообщает об ограничении. Норма и сбой записи обрабатываются без LLM.

Сквозной сценарий с OpenAI `gpt-6-luna` прошёл на выданных локальных заглушках ML/ТОиР. После предпросмотра и подтверждения получен TKT-0001. Локальный поиск нашёл ожидаемые страницы в 16 из 16 случаев. В последнем полном прогоне модели 14 из 16 положительных ответов содержали ожидаемый источник, восемь отрицательных дали ожидаемый отказ. Четыре намеренно неверные связки заблокированы. Полная смысловая и мобильная приёмка продолжаются. [Журнал работы](docs/validation/agent-worklog-2026-11-26.md).

### Локальный запуск Windows

Рекомендуемая среда продукта — Python 3.11+. Текущая реализация проверена на Windows с Python 3.15.2. Воспроизведение на Python 3.11 ещё требуется. Из корня репозитория:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
if (-not (Test-Path -LiteralPath '.env')) { Copy-Item .env.example .env }
```

Отредактируйте локальный `.env`: адреса заглушек, выбранный LLM_PROVIDER и модель. OpenAI требует OPENAI_API_KEY и OPENAI_MODEL. Yandex требует YANDEX_API_KEY, YANDEX_FOLDER_ID и полный YANDEX_MODEL вида `gpt://<folder>/<model>/<version>`. Ключи остаются на сервере, не передаются браузеру и не должны попадать в Git. Переменные процесса имеют приоритет над `.env`. Провайдер выбирается при запуске; смена требует перезапуска приложения, без переиндексации PDF.

Получите шесть PDF отдельно от организатора и положите в `документы/` с именами из [реестра](mechanic/manuals.py), либо задайте MANUALS_DIR. Затем:

```powershell
.\.venv\Scripts\python.exe -m mechanic.corpus
```

Подготовка сохраняет физические страницы, SHA256 документов, метаданные и FTS5/BM25 в `corpus/manuals.sqlite`. Фрагменты не пересекают страницы. Корпус строится во временной базе и заменяется атомарно; ошибка не уничтожает предыдущий индекс. Сканированные/малотекстовые страницы отмечены в `corpus/manuals.report.json`. Проверяется объединение кандидатов при обычном и сортированном извлечении текста. Формат базы имеет версию: после изменения схемы приложение требует перестроить индекс.

`--ocr` требует языковые данные Tesseract rus+eng; TESSDATA_PREFIX задаёт папку с файлами `rus.traineddata` и `eng.traineddata`. Языковые данные берутся из [официального tessdata_fast](https://github.com/tesseract-ocr/tessdata_fast); они должны быть доступны локально. Если данных нет, команда завершается понятной ошибкой до замены рабочего индекса. OCR применяется к значимому тексту сканов; проверенные обложки, схемы и страницы для заметок не прогоняются через OCR без необходимости.

### Проверка страниц и допуск нормативов

На Windows можно использовать установленный русский Windows.Media.Ocr вместо Tesseract. Подготовьте PNG физических страниц при 200 dpi в `corpus/review/ocr-inputs/`; повёрнутые страницы предварительно разверните (для 236 РК, PDF 144 — 90°). Команда запускает только собственный скрипт в отдельном процессе Windows PowerShell 5.1; постоянную политику выполнения не меняет:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -Command "& './scripts/ocr_windows.ps1' -ImagePath (Get-ChildItem -LiteralPath './corpus/review/ocr-inputs' -Filter '*.png' | Select-Object -ExpandProperty FullName) -OutputDirectory (Join-Path (Get-Location) 'corpus/review/windows-ocr')"
```

Скрипт требует установленный язык распознавания `ru`, сохраняет первичный текст и координаты слов только внутри `corpus/`. Исправьте результат по изображению в отдельном локальном UTF-8 файле, восстановите заголовки/столбцы, знаки и сноски. Запишите его через `python -m mechanic.review --manual 236-rk --page 144 --kind verified_ocr --rotation 90 --text-file corpus/review/verified-ocr/236-rk-144.txt`, повторите для остальных проверенных страниц и выполните `python -m mechanic.corpus` без `--ocr`. Этот импорт не требует Tesseract. Исходный OCR без визуальной сверки не допускается. Выполненный разбор: [отчёт 3.2](docs/validation/stage-3-ocr.md).

Реестр визуальной проверки — локальный `corpus/review/decisions.json`, привязанный к SHA256 PDF. Для записи решения после просмотра изображения:

```powershell
.\.venv\Scripts\python.exe -m mechanic.review --manual 236-rk --page 144 --kind scanned_table --rotation 90
```

Классы: illustration, cover, notes, scanned_table, scanned_text, verified_text, verified_ocr. Обложки и иллюстрации сохраняются в отчёте, но не считаются прочитанными нормативами. Для OCR сначала выполните `python -m mechanic.corpus --ocr`, сверяйте результат с изображением физической страницы, затем используйте `--kind verified_ocr --text-file <локальный UTF-8 файл>`. Файл должен содержать сверенный текст; не отмечайте страницу проверенной только потому, что OCR выполнился. После записи решений перестройте корпус.

Числовая рекомендация допускается только из визуально сверенной полной выдержки с единицами, условиями и применимыми двигателями. `--numeric-file` принимает локальный JSON-список объектов с полями `text`, `engines`, `mode` (operation или bench). Полный `text` должен присутствовать на странице и включаться в цитату целиком. Этот файл содержит извлечённый текст: храните его внутри `corpus/` и не публикуйте. Не объявляйте всю страницу или таблицу проверенной на основании одной строки. При замене PDF старое решение и старый индекс не разрешают выдачу источника; повторная проверка обязательна.

Режим обкатки/испытаний не подменяет эксплуатацию; явная другая модель или модификация отклоняется. При недостаточной теме или пустой выдаче приложение сообщает ограничение и запрещает заявку; пустой поиск не доказывает, что в оригинальном PDF нет инструкции. Смысловая LLM-проверка остаётся обязательной после этих серверных запретов.

Три терминала; во всех корень проекта. Заглушками на 8001/8002 управляет оператор: если они уже запущены, повторно эти две команды не выполнять и существующие процессы не останавливать.

```powershell
.\.venv\Scripts\python.exe -m uvicorn mock_ml.app:app --app-dir neurodvs_hackathon_mock_2026-11-16 --host 127.0.0.1 --port 8001
```

```powershell
.\.venv\Scripts\python.exe -m uvicorn mock_toir.app:app --app-dir neurodvs_hackathon_mock_2026-11-16 --host 127.0.0.1 --port 8002
```

```powershell
.\.venv\Scripts\python.exe -m uvicorn mechanic.app:app --host 127.0.0.1 --port 8000
```

Откройте http://127.0.0.1:8000. Единственный порт приложения — **8000**; дополнительный экземпляр на другом порту не запускайте. Порты 8001 и 8002 используются отдельными сервисами ML и ТОиР. Для проверки телефоном в доверенной локальной сети приложение можно запустить с `--host 0.0.0.0` и открыть адрес компьютера на порту 8000; серверные адреса ML/ТОиР остаются локальными. Публичное развёртывание без отдельной настройки доступа не предусмотрено.

Холодная подготовка PDF/индекса и установка зависимостей учитываются отдельно от запуска готового окружения. Требование запуска за пять минут проверяется на подготовленной локальной поставке; готовый индекс ради ускорения не публикуется.

### Работа с диагностикой и заявкой

Выберите машину и проверку. Двигатель берётся из карточки; у части МАЗ модель автомобиля отсутствует — она не выдумывается. Кнопка диагностики получает реальный результат ML по выбранной паре. Смена пары сбрасывает диалог, результат, черновик и подтверждение; запоздавший ответ скрывается интерфейсом. Вопрос по руководству может вызывать только RAG без новой диагностики. Цикл агента ограничен пятью шагами и 100 секундами, каждый вызов API — 30 секундами; разрешён один повтор временной ошибки LLM. Отказ или неизвестный результат ТОиР никогда не повторяется автоматически.

Статусы: normal — проверка не выявила отклонения; check_failed либо signal_quality=bad — повтор записи без диагноза и заявки; warning или confidence < 0.70 — явное предупреждение. Confidence не является риском; anomaly_score не используется как вероятность отказа. Высокий/низкий приоритет требуют подтверждённого руководством основания, средний — исходный уровень обоснованной дефектовки. При отсутствии документации отправка запрещена независимо от приоритета.

После обоснованного ответа запросите предпросмотр. Он содержит поля v6, работы с выдержками, запчасти (список может быть пустым), приоритет и ссылки manual/pdf_page. POST /tickets выполняется только по кнопке подтверждения действующего предпросмотра. Номер показывается только после 201 и валидного ответа ТОиР. При таймауте результат считается неизвестным; подтверждение расходуется, повтор автоматически не выполняется. После перезапуска заглушка нумерует заявки заново.

Ссылка на источник открывает одностраничный PDF для процитированной страницы текущего выбора. При `MANUAL_PAGES=0` сервер отключает маршрут PDF, а интерфейс сохраняет название документа, номер страницы и выдержку. Перед открытием стенда проверьте права на показ фрагментов руководств и настройте доступ к стенду.

### Журнал агента

[Dima: изменения, последние прогоны и инструкция по отладке](docs/validation/dima-debug.md).

Uvicorn выводит события агента на уровне INFO. По заголовку ответа `X-Action-Id` найдите записи одного действия в журнале сервера. В них видны шаги и инструменты, результат ML и поиска, итог проверки источников, подтверждённость отправки в ТОиР, длительность и числа токенов из ответа LLM API. Вопросы, ответы модели, выдержки, ключи и токены подтверждения журнал не пишет. Чтобы сохранить журнал локально в PowerShell, создайте папку `dist` и добавьте к команде запуска `2> dist/agent.log`. Для оценки расхода суммируйте токены по всем действиям одного сценария.

### Проверки

Диагностика показывает краткий вердикт: статус, тип, уверенность ML, риск и следующее действие. «Подробности и источники» раскрывает наблюдения, гипотезы, проверки, возможный ремонт, источники и ограничения. Неизвестный риск обозначается явно; технические рекомендации показываются только после проверки основания. При неподтверждённой смене машины/проверки кнопки действий блокируются. Интерфейс проверен в Edge, включая эмуляцию 375/320 px; физический смартфон и полный сценарий с настоящей LLM ещё требуют приёмки. [Отчёт 6.1/8.4](docs/validation/tasks-6-1-8-4.md).

При обнаружении противоречащих инструкций приложение показывает обе формулировки с документами и физическими страницами PDF, отмечает конфликт и рекомендует уточнить применимость у специалиста или производителя для конкретной модификации ДВС. Оно не выбирает одну версию как бесспорную, не показывает зависимую рекомендацию и блокирует заявку. Запрет хранится для выбранной пары в серверной сессии: старое подтверждение, повторный выбор или переключение и возврат его не снимают. Команда пользователя не заменяет уточнение; автоматического согласования с производителем в MVP нет. [Реализация и ограничения проверки 5.4](docs/validation/task-5-4.md).

```powershell
.\.venv\Scripts\python.exe -m pytest tests -q -p no:cacheprovider
.\.venv\Scripts\python.exe -m pytest neurodvs_hackathon_mock_2026-11-16/tests -q -p no:cacheprovider
.\.venv\Scripts\python.exe -m mechanic.evaluate
openspec validate hackathon-mvp --strict
```

Тесты приложения используют синтетические источники и контролируемые ответы API для проверки запретов и контрактов. Они не доказывают качество реальных ответов моделей или смысловую правильность нормативов. Для приёмки нужны реальные аккаунты, контрольный набор по design.md и ручная сверка с PDF. [Первый этап](docs/validation/stage-1.md) отдельно фиксирует проверки заглушек.

В `tests/data/retrieval_cases.json` зафиксированы 24 случая: 16 положительных, восемь отрицательных, восемь отмечены holdout. Вопросы и ожидаемые страницы не менялись при настройке поиска; массив защищён SHA256. Положительные страницы визуально сверены. Набор содержит вопросы и метаданные, без извлечённых текстов. `mechanic.evaluate` измеряет попадание ожидаемой страницы в первые пять результатов и отказ серверных проверок на отрицательных вопросах; результат сохраняется локально рядом с индексом. Это не приёмка смысловой верности реальной LLM: `live_model_semantics_verified` и `full_acceptance_passed` остаются false.

Дополнительные проверки блока 8: при уже работающих ML/ТОиР задайте `MECHANIC_LIVE_CHECKS=1` перед pytest, чтобы включить `tests/test_live_services.py`. Этот тест проходит 195 пар через приложение и настоящий ML, намеренно отключает LLM и не отправляет заявки; по умолчанию пропускается и сервисы не запускает. При установленном Node.js `node --test tests/frontend.test.cjs` проверяет отображение предупреждения при ошибке генерации с DOM-двойником. Node.js не нужен для запуска продукта. Эти проверки не заменяют реальную смысловую и мобильную приёмку; команды и результаты — в [отчёте блока 8](docs/validation/stage-8.md).

### Публикация и лицензии

PDF, текстосодержащие индексы, выгрузки и дампы запрещено размещать в открытом репозитории. .gitignore исключает локальные пути; перед публикацией отдельно проверяются текущие файлы, история ветки, LFS и релизы. В истории исходных пользовательских веток уже есть PDF: эти ветки нельзя отправлять как есть. История не переписывалась автоматически.

Лицензии и условия PyMuPDF перечислены в [THIRD_PARTY.md](THIRD_PARTY.md). Правила платных API и их биллинг отличаются от подписки ChatGPT. Цена пользовательского действия включает несколько обращений: выбор инструментов, генерацию и проверку основания. Перед запуском проверить тарифы [OpenAI](https://developers.openai.com/api/docs/pricing) и [Yandex](https://aistudio.yandex.ru/ru/docs/ai-studio/pricing), доступность модели, страну аккаунта, оплату, лимиты расходов и квоты. Для текущего `gpt-6-luna` [официальный тариф](https://developers.openai.com/api/docs/models/gpt-6-luna) стандартного режима короткого контекста — $0,10 за миллион входных и $0,50 за миллион выходных токенов: условные 20 тысяч входных и 2 тысячи выходных токенов за весь цикл стоят $0,003. Это пример арифметики, а не замер приложения; детали и пробелы в [расчёте стоимости](docs/delivery/cost-estimate.md). Фактическая стоимость и доступность по региону и квотам аккаунта пока не подтверждены; образцы бюджета в design.md не являются текущей котировкой.

`python -m mechanic.package` создаёт `dist/digital-mechanic-source.zip` по списку разрешённых исходников: без PDF, корпуса, изображений сверки, секретов и каталога .git. Архив ничего не публикует. Шесть PDF исключены из текущего индекса Git без удаления локальных файлов; старая история исходных веток всё ещё содержит PDF, и её нельзя отправлять как есть. Отчёт этапа 3: [stage-3.md](docs/validation/stage-3.md).

Используется уже установленная Python-среда; установка зависимостей и полный OCR в этот замер не входят. Сервисы организатора не запускаются и не перезапускаются. Локальные отчёты и текстовый индекс остаются внутри игнорируемого dist/.

## Инструменты разработки

Для установки в облачной среде Linux нужен Node.js 22.20.0 или новее.

```bash
bash scripts/install-dev-tools.sh
export PATH="/workspace/.local/bin:$PATH"
export OPENSPEC_TELEMETRY=0
```

- `openspec list` показывает активные изменения OpenSpec. Для подготовки нового изменения используйте навык `$openspec-propose` в Codex.
- `rtk git status` выводит краткий статус Git. RTK можно вызывать явно из терминала.
- `deslop-please` проверяет архитектуру Rust-проекта. Для проверки нужны Cargo и рабочая область Rust.

По умолчанию команды устанавливаются в `/workspace/.local/bin`. Задайте `DEV_TOOLS_PREFIX` перед установкой, чтобы выбрать другой каталог, и добавьте его подкаталог `bin` в `PATH`.
